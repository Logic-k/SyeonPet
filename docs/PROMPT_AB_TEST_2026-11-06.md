# AI 정리 지시문 A/B 시험 (2026-11-06)

v0.2.8에서 AI 정리 지시문(`optimizer_ai.SYSTEM`)을 고쳤습니다. 이 문서는 그 근거와 한계를 적습니다. 모든 요청은 가상 업무 사례이며, 결과는 시험한 시점의 공유 무료 모델에서 관찰한 값입니다.

## 방법

- 공급자는 두 곳입니다. JarvisClaw `auto/free`(앱 기본값)는 호출마다 nemotron-3-super-120b 또는 nemotron-3-nano-30b reasoning으로 연결됐습니다. Kilo Gateway `kilo-auto/free`는 비교용이며 앱에는 포함하지 않았습니다.
- 요청 형식은 앱과 같습니다. 같은 지시문과 같은 JSON 입력(`original_request`, `context`, `revision` 등)을 보냈습니다.
- 사례는 31개입니다.
  - 기존 `tools/benchmark_free_ai.py`의 11개
  - 처음 보는 사례 10개(번역, 모호한 요청, 엑셀 수식, 민원, 확정 역할 블록, 수정 요청, 영어 요청 등)
  - 1차 결과를 본 뒤 새로 만든 사례 10개(분량 지정, 자료 누락, 교육지원청 회신, 학교 문의문, 금지 여러 개, 코딩 등)
- 사례마다 2회씩 호출했고, 안의 순서는 무작위로 섞었습니다.
- 채점은 출처를 가린 채로 했습니다. 사례마다 채점자 2명이 따로 판정했고, 판정 항목은 다음과 같습니다.
  - 일을 직접 했는지, 역할을 혼동했는지, 사실을 지어냈는지
  - 미확정 내용을 확정으로 바꿨는지, 조건을 누락했는지
  - 요청하지 않은 제한을 넣었는지, 언어나 자료를 바꿨는지
  - 품질 점수(1~10점)
- 두 채점자의 점수 차이는 평균 0.37점이었습니다.

## 1차: 새로 설계한 안 3개와 현재 지시문 (사례 21개)

| 안 | 평균 품질 | 사실·역할 등이 틀린 비율 | 요청하지 않은 제한 |
|---|---|---|---|
| 현재 지시문 | 6.71 | 20% | 40 |
| 예시 중심안 | 6.77 | 25% | 12 |
| 구조 우선안 | 6.30 | 21% | 13 |
| 경량안 | 6.05 | 31% | 16 |

새로 쓴 안들은 현재 지시문을 이기지 못했습니다. 현재 지시문의 약점은 따로 드러났습니다. 결과물에 요청하지 않은 분량 제한(예: "5~7줄", "4문장 이내")이 붙는 것입니다. 지시문 예시의 "인사 1줄, 안내 3~4줄"과, 요청문 길이를 뜻하는 "보통 5~12줄"이 결과물 조건으로 옮겨진 것으로 보입니다.

## 2차: 현재 지시문과 하이브리드 (사례 31개)

현재 지시문에서 다섯 곳만 고쳤습니다.

1. "5~12줄"은 이 요청문의 길이일 뿐 결과물의 분량이 아니라고 밝히고, 예시의 줄 수 지정을 지웠습니다.
2. "자료:" 줄은 자료가 필요한 작업에만 두게 했습니다.
3. 반말 지시는 정중한 요청체로 바꾸고, 날짜 표기는 원문 그대로 두게 했습니다.
4. 문의·회신 요청에는 "문의자 / 답변 작성자 / 수신자" 줄을 두게 했습니다.
5. 받는 AI가 볼 수 없는 "원문 그대로" 같은 표현을 쓰지 않게 했습니다.

| 구분 | 현재 | 하이브리드 |
|---|---|---|
| 전체 평균 품질(각 234건) | 6.26 | 6.24 |
| 요청하지 않은 제한 | 69 | 28 |
| JarvisClaw의 틀린 결과 비율 | 35% | 26% |
| Kilo의 틀린 결과 비율 | 5% | 11% |
| 처음 보는 사례 10개의 품질(1차 결과를 본 뒤 만든 사례) | 6.11 | 6.54 |
| 기존 사례 11개의 품질 | 6.27 | 5.74 |
| 숫자·조건 누락 | 13 | 20 |

같은 사례·같은 회차끼리 짝지어 비교하면 품질 차이는 −0.02점이고, 95% 부트스트랩 구간은 −0.38~+0.32입니다. **전체 품질이 좋아졌다고 말할 근거는 없습니다.**

그래도 고친 지시문을 채택한 이유는 세 가지입니다.
- 사용자가 직접 확인하게 되는 요청하지 않은 분량 제한이 약 60% 줄었습니다.
- 앱의 기본 AI인 JarvisClaw에서 사실·역할이 틀린 결과의 비율이 낮았습니다.
- 숫자 누락은 앱이 원문을 다시 붙이는 검사(`keep_original_details`)로 일부 보완됩니다.

## 한계

- 사례마다 2회만 시험했고, 공유 모델의 연결 대상과 부하가 바뀝니다.
- 이 결과로 특정 업무에서의 정확도나 개선률을 주장할 수 없습니다.
- 기존 사례 일부(기초학력, 공개자료 요약, 교육지원청 문의, 확정 역할 블록 2)에서는 점수가 떨어졌습니다.
- Kilo는 시간당 200회 한도에 걸려 일부 응답을 받지 못했습니다. 그래서 두 안의 결과가 모두 있는 사례·회차만 비교했습니다.
- AI 결과는 사용 전에 반드시 원문과 대조하세요.
