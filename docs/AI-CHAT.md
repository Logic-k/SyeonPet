# 데스크탑 펫에 AI 대화 기능 — 리서치

> **이전 조사 기록:** 아래의 일반 대화 UI와 `providers.py` 연결 설명은 과거 구현에 대한 기록입니다. 현재 션의 대화창은 프롬프트 정리 전용이며 일반 대화 탭은 제공하지 않습니다. 아래 모델 이름, 무료 한도, 가격, 지연 및 추천은 작성 당시의 확인되지 않은 추정이 포함되어 현재 이용 조건으로 사용하면 안 됩니다. 현재 기능과 외부 전송 안내는 [프롬프트 정리 사용법](PROMPT_TOOLKIT_INTEGRATION.md)을 참고하세요.

## 1. 기존 사례 (이 시장에 이미 있는 것들)

| 프로젝트 | 방식 | 특징 |
|---|---|---|
| **PetGPT** (GitHub) | 멀티-LLM(OpenAI/Gemini/Claude/Grok/Ollama) + MCP + 로컬 메모리 | Tauri/Rust, 텔레그램·QQ 그룹챗 자율 참여까지 하는 "소셜 에이전트" |

| **Desktop-Virtual-buddy** | Electron + Shimeji 46포즈 + 분리형 LLM 브레인 | 벽/천장 기어오르기, 창 위 앉기. LLM 없이도 동작, 붙이면 상황인지 행동 |
| **Shimeji AI 모드들** | 대부분 OpenAI 키 입력 방식 | 대화창 띄워서 펫과 대화 — 가장 흔한 패턴 |

공통점: ① 대화는 별도 창/말풍선 ② 페르소나를 시스템 프롬프트로 ③ LLM 없을 땐 규칙기반 응답 ④ 화면 인식(멀티모달)은 고급 옵션.

## 3. 이전 일반 대화 구현 패턴

**구현한 것**: 트레이 "션과 대화하기" → 펫 옆 대화 패널. providers.py의 `make_brain()`이 config를 보고 선택:
- `provider: "canned"` — 키 없이 동작하는 규칙응답(기본값, 오프라인)
- `provider: "gemini"` + `api_key` → Gemini REST 직접 호출(표준라이브러리 urllib만 사용 — 의존성 0)
- `provider: "openai_compat"` + `api_key` + `base_url` → Groq/OpenRouter/OpenAI 호환 `/chat/completions`

**페르소나 설계**: `config.json`의 `chat.persona`로 시스템 프롬프트 주입 — "션은 부산교육청 마스코트, 존댓말, 1-2문장, 귀여운 리액션"처럼 정의. 비우면 내장 기본값 사용. 응답 시 펫이 살짝 인사(wave) 연출.

**메모리**: 최근 20턴(질문+답변 쌍)을 컨텍스트로 보냄 — 짧은 대화 연속성. 영구 메모리(SQLite 요약)까지는 오버엔지니어링이라 제외.

**비동기**: HTTP는 QThread 워커 — 응답 기다리는 동안 펫은 계속 걸어다님(UI 프리즈 없음). 실패 시 패널에 부드러운 오류 문구.

## 4. 한계·주의점

- **키 관리**: config.json에 평문 저장 — 개인 PC용이면 괜찮지만 배포 시 키를 같이 넣지 말 것(키가 새어나가 남용됨)
- **무료티어 한도 초과**: Gemini 일 한도 넘으면 오류 → canned로 자동 폴백하는 건 구현 안 함(재시작 전까지 오류 표시)
- **스트리밍 미지원**: 답변이 통째로 옴(1-2s). 스트리밍하려면 SSE 파싱 추가 필요
- **멀티모달(화면 보기)**: Mochi처럼 하려면 스크린샷→Gemini vision. 개인정보 우려 + API 비용 — 필요하면 말씀 주세요
