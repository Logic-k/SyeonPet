# Windows 패키지와 업데이트 안내

## 실행

이 프로젝트는 Python과 PySide6로 동작합니다. `SyeonPet.exe`는 같은 폴더의 `main.py`와 포함된 Python 런타임을 실행하는 런처이며, `run.cmd`는 대체 실행 방법입니다. 둘 중 하나만 옮기는 독립 실행 파일은 아닙니다. 소스와 `assets`, Python·Qt 런타임 및 설정 파일을 함께 유지해야 합니다.

기존 런처가 같은 폴더의 합성 `main.py`를 실행하는 동작은 별도 임시 폴더에서 확인했습니다. 이 시험만으로 새로 생성한 ZIP의 완전성이나 다른 PC의 실행까지 보장할 수는 없습니다.

기존 런처는 코드 서명되지 않았습니다. Windows가 실행 전 신뢰 여부를 물을 수 있으며, 다운로드한 파일은 공식 릴리스 위치와 공개된 SHA-256을 확인하세요.

## 첫 설치와 기존 데이터

v0.1.5 이하에서는 자동 업데이트를 지원하지 않습니다. 자동 업데이트를 지원하는 버전으로 처음 옮길 때 아래 방법으로 한 번 설치하세요.

1. 기존 션에서 필요한 대화 내용을 보관함에 저장하거나 복사하고 앱을 종료합니다.
2. 새 ZIP을 **기존 앱과 다른 폴더**에 풉니다. ZIP에는 배포용 기본 `config.json`이 들어 있으므로 기존 폴더에 그대로 덮어쓰면 개인 설정을 잃을 수 있습니다.
3. 새 폴더에서 `SyeonPet.exe` 또는 `run.cmd`를 실행합니다. 기존 설정을 쓰려면 먼저 기존 `config.json`을 별도로 백업한 후 내용을 확인하고 직접 옮깁니다. 설정이나 보관함을 삭제하는 과정은 없습니다.
4. 션 보관함은 사용자별 로컬 저장 공간에 별도로 존재합니다. 이전 전에 프로그램에서 JSON 백업을 보관하고 새 환경에서 결과를 확인하세요. 브라우저 기반 기존 프롬프트 툴킷의 보관함은 별도이며 JSON 가져오기로 사용자가 선택해 옮길 수 있습니다.

실제 개인정보·비공개 문서는 외부 AI에 전송하기 전 기관의 정책과 허용된 서비스를 확인해야 합니다. 기본 정리는 외부 전송 없는 구조화 기능이며 AI 재작성은 아닙니다.

## 자동 업데이트 사용

자동 업데이트를 지원하는 버전에서는 앱이 시작 시 공식 GitHub의 최신 안정 릴리스를 백그라운드에서 확인합니다. 션 우클릭 또는 트레이 메뉴의 **업데이트 확인**으로도 확인할 수 있습니다. 새 릴리스의 업데이트 정보가 앱에 고정된 공개키의 서명과 일치하고 ZIP도 검증되면 사용자별 별도 폴더에 미리 준비합니다. 준비가 끝나면 안내가 표시됩니다.

적용하려면 트레이 또는 션 메뉴의 **종료**로 션을 종료한 다음 원래 사용하던 실행 경로로 다시 실행하세요. 여러 션을 켠 경우 모두 종료해야 합니다. 업데이트를 위해 정상 종료할 때 대화 입력·편집 결과·템플릿 초안을 `%LOCALAPPDATA%\SyeonPet\updates` 아래 설치별 `drafts` 폴더에 보관하고 다음 실행에서 복원을 시도합니다. 복원 후 정상 종료하면 복구 원본은 `.restored` 파일로 남습니다. 이 파일에는 대화 내용이 **암호화되지 않은 텍스트**로 포함되므로 사용자 계정과 저장 공간을 안전하게 관리하고 사용자만 접근할 수 있는 PC를 권장합니다. Windows 종료나 프로세스 강제 종료에는 이 보존 절차가 보장되지 않습니다. AI 처리나 확인 대화상자가 진행 중이면 작업을 마치고 다시 종료해야 합니다.

여러 션에서 각각 보관한 초안은 따로 저장되며, 다시 실행한 창 하나에서 초안 하나씩 복원합니다. 모든 창이 한 번에 자동으로 다시 열리지는 않으므로 여러 초안이 있었다면 필요한 만큼 션을 다시 실행해 각각 확인하세요.

원본 설치 경로의 `config.json`, 사용자별 보관함과 설정을 사용하며, 업데이트 파일은 기존 설치 폴더에 덮어쓰지 않습니다. 후보 버전의 실행·초기화가 실패하면 이전 버전 또는 원본 설치로 돌아가도록 설계되어 있고 복원용 초안 파일도 유지합니다. 통신·서명 검증에 실패하거나 인터넷이 없으면 기존 버전을 계속 사용할 수 있습니다. 강제 종료, 하드웨어 고장 등 모든 상황에서 작업 복원을 보장하는 것은 아니므로 중요한 작업은 보관함 저장 후 JSON으로 별도 백업하세요. 보관함 JSON에는 저장된 항목만 들어갑니다.

## 패키지 생성

Windows에서 저장소 루트를 기준으로 Python 3.10 이상을 사용합니다. 다음 명령은 `version.py`의 버전과 일치해야 하며 ZIP은 저장소 밖의 **아직 존재하지 않는** 경로에 생성합니다.

```powershell
python tools/build_release.py --version 0.1.6 --output <새_출력_폴더>/SyeonPet-0.1.6-windows.zip
```

필요하면 `--revision <40자리_커밋_SHA>`를 추가해 패키지 대상 파일이 해당 커밋과 일치하는지 검사할 수 있습니다. 스크립트는 기존 ZIP과 `.sha256`을 덮어쓰지 않고, 허용 목록에 있는 런타임·소스·자산만 포함합니다. 사용자 `config.json` 대신 공개 기본 설정을 사용하고, 보관함과 로컬 인수인계 문서는 넣지 않습니다. ZIP의 `package-manifest.json`에는 포함 파일별 SHA-256이 기록됩니다.

배포 전에는 별도 폴더에 풀어 런처·프롬프트 정리·수면·우클릭·업데이트 확인과 인터넷 단절을 시험하고, 라이선스·캐릭터 사용 권한 및 배포 대상을 확인해야 합니다. 제3자 런타임 고지는 패키지 `licenses/THIRD_PARTY.md`에 담깁니다. 이 안내는 라이선스 의무의 충족이나 특정 기관의 서비스 승인을 보증하지 않습니다.

## 업데이트 서명과 배포 담당자 안내

서명 업데이트 기능이 포함된 버전부터는 ZIP과 별도로 버전별 업데이트 정보 및 Ed25519 서명 파일이 필요합니다. 배포 담당자는 빌드한 ZIP을 검증한 뒤 **별도 보관 중인 개인키**와 OpenSSL 3을 이용해 서명합니다. 개인키는 저장소, 릴리스 자산, 배포 ZIP, 문서 또는 로그에 넣지 마세요. 앱에 포함된 공개키와 일치하지 않는 개인키는 서명 도구에서 거부됩니다.

```powershell
python tools/sign_update.py --archive <검증한_SyeonPet-X.Y.Z-windows.zip> --private-key <별도_보관한_개인키_PEM> --output-dir <새_서명_파일을_보관할_폴더> --openssl <OpenSSL_3_실행_파일>
```

출력 폴더에는 `SyeonPet-X.Y.Z-update.json`과 `SyeonPet-X.Y.Z-update.sig`가 생깁니다. 각각 이미 존재하면 덮어쓰지 않습니다. 같은 버전의 ZIP, 업데이트 JSON, 서명 파일을 공식 GitHub 릴리스에 함께 게시해야 앱에서 서명을 검증할 수 있습니다. ZIP의 `.sha256`은 별도 무결성 확인에 사용할 수 있지만 서명 대신 사용할 수는 없습니다. 새 버전을 실제로 준비·적용·복구하는 전체 과정을 별도 시험 환경에서 확인한 뒤 배포하세요.

개인키가 유출되거나 사라지면 공개키가 고정된 기존 앱의 신뢰 관계를 그대로 유지할 수 없습니다. 개인키 접근 권한을 제한하고 안전한 오프라인 백업과 사고 대응 절차를 마련하세요. 키 교체에는 새 공개키를 포함한 앱을 사용자가 신뢰할 수 있는 경로로 다시 설치하는 절차가 필요할 수 있습니다. 업데이트 메타데이터 서명은 Windows 실행 파일 자체의 Authenticode 서명과 다르며, 서명하지 않은 실행 파일에 표시되는 Windows 경고를 없애지 않습니다.
